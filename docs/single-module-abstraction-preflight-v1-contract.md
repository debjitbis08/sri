# Single-module abstraction preflight v1

**Status:** prospective analytical contract, 2026-10-25. The algebraic
observation in section 3 was derived while drafting this contract; no
numerical preflight or relational learner has run. Commit this document
before implementing or executing the finite checks below.

Follows the [current design](single-module-plasticity-design.md),

## 1. Purpose and boundaries

Operational hypothesis: a learned abstraction captures a predictive relation
that transfers selectively across changed realizations. Preserving relations
while responding to relation-changing differences is required. Depth,
compression, stable inner parameters and denoising quality alone are
insufficient. The whole representation need not be invariant: reconstructing
rotated evidence can require an appropriately rotated response.

Before a learning study, establish:

1. The visible evidence identifies the intended answer, and the proposed
   split tests combinations absent from training.
2. Simple linear completion, collapse, local appearance and lookup do not
   automatically satisfy the intended interpretation.
3. The energy/interface admits useful completion, or its obstruction is
   identified before spending a learning budget.
4. Any claimed inner contribution has an intervention that preserves a
   well-defined inference problem and appropriate controls.

This preflight performs proofs, finite enumeration, linear-reference fits and
bounded numerical identity checks. It does not train the circular module,
select its learning rates, install a new architecture, or open a confirmation
set. An inconclusive capacity result remains inconclusive. A failed optimizer
would not constitute a proof of inability.

## 2. Exact minimal relational fixture

Four parts occupy four known contiguous eight-coordinate outer sectors
(phase zero for this analytical task). Each part's orientation has eight
values. Let t in {0,...,7}, r in {1,2,3}, j in {0,...,3}, and

```
theta_j = 2*pi*(t + j*r)/8
s_j = (cos(theta_j), sin(theta_j), 0,0,0,0,0,0)
```

There are 24 clean scenes. Reveal sectors 0 and 1; predict sectors 2 and 3.
Visible evidence determines r modulo eight from the relative orientation,
then determines the missing parts. The hidden target has squared norm 2,
equal to the visible input's squared norm. Missing-part loss is
`||prediction_hidden - s_hidden||^2 / 2`; zero prediction scores 1.

Use three angular steps deliberately. A two-rule fixture can accidentally
admit one linear completion map on the union of its input subspaces. Whether
one linear map solves this three-rule fixture must be checked explicitly.

Design split: hold out (r,t) exactly when `t mod 3 == r-1`. Each r occurs in
training and evaluation; each t occurs in training under other r values.
Report the complete split, all part-orientation counts, and rule-conditional
marginals. This split is not claimed to balance every marginal. It is a
small analytical fixture, not 24 independent statistical replicates.
For rule-conditional metrics, macro-average the three rules before averaging
worlds. Do not choose a different split after inspecting comparator errors.

For each t, all three r share the same first part but different relationships.
Also enumerate orientation-matched pairs at every individual sector over the
full fixture. These counterexamples audit local shortcuts and the ability to
preserve relationship distinctions. Record which are in each split.

Optional-looking choices below are fixed parts of this preflight:

- Identity rendering, with the explicit coordinates above, is the algebraic
  reference. It is a disclosed input representation, not learned perception.
- Four numerical fixture worlds apply independent orthogonal 8x8 matrices
  O_j per sector to the same clean scenes. The matrices are generated by
  Gaussian QR with positive R diagonal. This hides the signal coordinates
  without changing norms or mathematical identifiability.
- No texture or observation noise is included in these feasibility checks.
  A subsequent learning contract must add independent nuisance variation
  and fresh views; this clean preflight cannot establish robustness to texture.

The fixture oracle knows the rendering and modular rule. It is evaluator-only
and cannot initialize or supply targets/labels beyond the declared predictive
training data to any later learner. Oracle feasibility is task feasibility,
not module capacity.

## 3. Analytical observation: the current zero-filled interface has a floor

Keep the exact v1 energy and actual output x_0, with no output rescaling or
decoder. For any fixed second-pass route a, write its structural Hessian K
without the outer anchor. K is positive semidefinite. Its inner block K_II
is positive definite: with x_0=0, zero inter-ring residuals and full-column-
rank maps force each successive inner state to zero. Eliminating inner states
gives the positive semidefinite Schur complement

```
S_a = K_00 - K_0I K_II^(-1) K_I0
F_a = alpha * (alpha*I + S_a)^(-1), alpha=0.1
x_0 = F_a h
```

Thus F_a is symmetric and `0 <= F_a <= I` in the positive-semidefinite order.
For disjoint visible and hidden coordinate projections V and H,

```
||H F_a V||_2 = ||H (F_a - I/2) V||_2 <= 1/2.
```

When hidden input coordinates are filled with zero,
`||prediction_hidden|| <= ||h_visible||/2`. In the clean fixture, visible
and hidden true signals have equal norm, so the reverse triangle inequality
gives missing-part loss at least **1/4** for every scene and every allowed
parameter setting. This holds pointwise when routes depend on h: each realized
second-pass F_a still has the stated property. It does not assert that the
overall routed function is linear or globally nonexpansive between inputs.

Audit this derivation and its assumptions independently against the source.
The bound applies to raw zero-filled input and the actual output; it is not a
general lower bound for a mask-aware interface, a rescaled decoder, arbitrary
corruption noise, or a different energy. Do not evade it by crediting
direction-only accuracy while omitting amplitude error.

Consequently, a later clean completion target below 0.25 cannot be used to
judge the unchanged zero-filled module's ability to learn a relation. Do not
launch a parameter-fitting sweep to try to overcome this proven floor.

## 4. Analyze explicit observation masks before adoption

Analyze, but do not adopt as the learned candidate, the following interface
extension. Replace the outer term by

```
alpha/2 * sum_i m_i (x_0,i - h_i)^2
```

where m_i=1 for observed coordinates and 0 for missing coordinates. Use the
same mask in pilot and second inference, with right-hand side alpha*m*h.
Missing coordinates are unconstrained by data, rather than anchored to zero.
The mask is supplied observation metadata available to every comparator;
it contains no hidden orientation or rule identity.

Prove or refute uniqueness for the declared mask and all allowed maps. A
candidate argument is that positive lateral cycle terms force a zero-energy
state to be constant on each ring, one observed coordinate forces the outer
constant to zero, and full-rank radial maps then force inner states to zero.
Check every premise, especially the reliance on strictly positive lateral
coupling. Report conditioning; uniqueness does not imply good conditioning.

Derive the full map and its Schur equivalent with the mask. Establish which
parts of section 3 cease to apply. Investigate the actual remaining capacity
restriction: learned radial maps remain sector-supported, while lateral
cross-sector connections are fixed. Do not infer representational sufficiency
from a path through the graph or from positive definiteness.

Capacity classifications are `constructive_witness`, `proved_obstruction`,
or `unresolved`. A witness must give one permitted parameter setting and one
unchanged inference policy for all 24 scenes, with clean missing-part loss
<=0.10 on every scene and correct nearest-orientation prediction in both
missing sectors. Provide full numeric parameters and verify all constraints;
parameters selected separately for each scene are not a witness. The 0.10
threshold is a feasibility target fixed here, not an empirical abstraction
criterion. No unbudgeted numerical search for a witness is authorized here.
If algebra does not settle capacity, recommend a separately specified bounded
search or architecture revision. No need to force a binary conclusion.

## 5. Finite task and comparator audits

Enumerate all 24 scenes under each of the five renderings (identity plus
four orthogonal fixture worlds). Use float64 and direct SVD least squares,
relative singular-value cutoff 1e-12, minimum-norm coefficients and an
explicit intercept. Fit on the declared training split only and freeze:

1. Constant hidden-output predictor: training mean.
2. First-visible-part-only affine predictor.
3. Affine predictor from both visible parts.
4. Nearest training input in visible Euclidean distance; ties resolved by
   lexicographic (r,t). Return that example's hidden target.

Also fit the affine two-part predictor to all 24 scenes as a separately
labelled oracle capacity audit. It is not a legitimate held-out baseline.
Derive its exact algebraic residual or subspace obstruction where possible;
check the numerical residual agrees. Report all errors, including per-rule
and worst-scene loss, and nearest-orientation accuracy for each hidden part.
Nearest-orientation decoding uses the known rendering only in the evaluator.

Any valid comparator solving the held-out fixture is a finding to retain.
If a fixed affine predictor solves it, the fixture cannot establish a need
for nonlinear relational inference. Lookup success narrows the claim about
unseen combinations. Do not weaken comparators or silently change the rule
set/split. Revise the future task in a new dated contract if necessary.

**Pre-execution numerical clarification (2026-10-25):** enumerate scenes in
lexicographic (r,t) order. Treat distances within absolute 1e-12 of the
minimum as ties for nearest-neighbor prediction and orientation decoding;
resolve by scene order and smallest orientation index respectively. This
prevents floating-point rotations from changing mathematically tied choices.
Report macro-rule and ordinary scene means explicitly. Generate radial blocks
in ring-major, then sector-major order, followed by four terminal vectors.
Retain full precision for checks and serialize scientific floats to 12
significant digits, as in the existing studies. These conventions were fixed
before any finite checks or comparator results were computed.

## 6. Numerical identity checks and provenance

Root `2026102502`; RNG keys `[root, world, part]`, worlds 0..3. Part 0 draws
four O_j Gaussian matrices in sector order. Parts 1..4 each draw one set of
independent Gaussian radial blocks and terminal vectors, applying v1 positive-
diagonal QR/unit normalization. Thus there are 16 parameter fixtures. This
is arbitrary constrained initialization, not privileged source acquisition.
All fixtures use phase zero and the v1 topology/coefficients/gate formula.

For every parameter fixture and 24 rendered scenes, check both original
zero-filled inference and the proposed masked inference, under all-one routes
and matched two-pass routing. No parameter updates, restarts, search or tuning.
One deterministic scientific execution plus one repeat must be byte-identical
in the pinned single-thread float64 NumPy/SciPy environment.

Check energy/Hessian expansion, symmetry, positive definiteness, full/Schur
agreement, and the original-interface contraction bound with independent
linear algebra. Use v1 constraint 1e-9, relative residual 1e-10, Schur
agreement 1e-9, and allow 1e-9 numerical slack for the contraction/loss floor.
Record eigenvalue/condition ranges and gate extremes. Distinguish a
mathematical counterexample from numerical failure; preserve the failing
fixture and stop on correctness failure rather than repairing the system.

An observed random fixture succeeding is a capacity witness only if it meets
section 4 on all scenes. Failure of all 16 random fixtures is not a capacity
obstruction. Numerical confirmation of a bound supplements its proof.

Freeze new source/test hashes and contract hash before execution; record
frozen v1 dependency hashes without changing those files. Record interpreter,
library versions, revision, commands and dirty paths. Keep the deterministic

## 7. Obligations for a subsequent abstraction learning contract

This section specifies required evidence, not permission to start an
underspecified training experiment. After preflight, a new prospective
contract must fix the candidate interface/architecture, noisy observation
generator, training objective, initialization, budgets and held-out split.

- Train from multiple realizations with recurring relations and independent
  nuisance. Declare exactly what each paired observation shares. All learners
  get the same masks, views and supervision; clean oracle targets remain
  evaluator-only unless explicitly shared with all methods as supervision.
- Freeze learning at evaluation. Primary evidence is completion on unseen
  combinations and correct discrimination of matched relation-changing cases.
  Report amplitude-sensitive error as well as discrimination; collapse fails.
  Few-example adaptation is separate from reuse without updates.
- Include local, flat linear and a suitable nonlinear predictive comparator,
  a frozen/untrained module, and a relation-disrupted training control. Define
  disruption so single-part marginals and nuisance statistics are preserved.
  Freeze comparator tuning budgets and selected configurations before scoring.
- Probe outer and inner states with the same fixed, simple readout family.
  Fit probes on separate calibration data within the training combinations,
  freeze them, and test transfer. Count labels, calibration, fitting and
  selection. Decodability alone does not establish use.
- Specify an inner-contribution intervention and a control for generic
  damage. Recompute a valid equilibrium after a structural intervention;
  overwriting a settled state after producing the output cannot test use.
  Beware that removing inner links may destroy uniqueness under a mask.
  No silent diagonal repair or intervention-specific decoder retraining.
- Report performance before training, after learning, and after nuisance
  changes. Establish that any successful relation was acquired rather than
  fully installed by initialization or a supplied oracle.
- Treat independently generated worlds as replicates. Fix practical margins,
  multiplicity handling, sample counts and a joint anti-collapse criterion
  before confirmation. No test-based task selection or selected checkpoint.

Behavioral selective transfer supports a narrow relational abstraction claim.
Transferring probes add representation evidence; controlled functional
interventions add evidence of use. None alone establishes a general advantage
of layering, slow learning, or reciprocal settling.

## 8. Time, storage, measurements and deliverables

Let N=24 scenes, d=32, M=80, J=L=4, P=328, and p<=17 affine input features
including intercept. Scene construction is O(Nd); sector rendering is
O(NJq^2), q=8. Each orthogonal renderer costs O(Jq^3).
SVD least squares costs O(n p min(n,p) + n p d); prediction costs O(N p d).
Nearest-neighbor evaluation costs O(N n d), retaining n training pairs.
Record train/all-scene fits separately, with no hyperparameter search.

Curvature assembly costs O(LJ M^2); each dense Hessian factorization, full
eigenspectrum and Schur-complement construction costs O(M^3), with O(M^2)
workspace. A cached-factor solve costs O(M^2). Routes add O(P) per input;
route-dependent factors generally cannot be shared between inputs. Count
both pilot and second solves, Schur references, eigenspectra and repeated
verification. Total work scales with the 16 parameter fixtures, 24 scenes,
two interfaces and two route policies, plus the deterministic repeat. No
learning updates or tuning executions are charged because none are performed.

Parameters occupy 2,624 bytes plus metadata. Dense curvature cache occupies
819,200 bytes; one dense 80x80 matrix occupies 51,200 bytes. The mask occupies
32 bytes if bool, or 256 bytes if float64; record actual dtype and allocations.
Retained affine weights use O(p d) values, lookup O(n d) input/target values,
and all scene/fixture arrays belong to the harness. Record allocated bytes and
process peak RSS separately; persistent parameters are not a workspace bound.

For this small analytical study, whole-run wall/process CPU and peak RSS,
plus separate enumeration, comparator fitting and solver-check phase times,
are sufficient. Record CPU/OS/BLAS, threads, repeat count, fits, scenes,
factors/solves, source hashes and all failed work. Null unavailable quantities
with reasons. Do not sum nested timers or infer FLOPs from parameter counts.

Use new source/runner/tests and report prefix
`single-module-abstraction-preflight-v1` for manifest, deterministic results
and runtime JSON. Put proofs, counterexamples, interface recommendation and
capacity classification in docs/. Preserve all historical artifacts.

The final decision must state whether the task is identifiable, whether its
split defeats the declared simple explanations, and whether the interface
and architecture can meet the completion target. An unresolved capacity
question leads to another bounded analytical step, not an unsupported claim
that slow inner learning will create abstraction.
