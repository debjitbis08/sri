# Everyday relations v1: what the two-space core learns from facts

Status: **draft contract, 2026-11-05. Not frozen; awaiting user review.**

User direction (2026-11-05), a detour from the counting line: test the two-space core with readers on many kinds of relations,
to see which it learns and whether it forms abstractions for them. Inputs can be whatever is fastest; no images or taps.
Language and grammar matter most, followed by real-world relations (the animal kingdom, colours and other concepts taught to
small children).

This is a core-only study. Memory is absent by design. The program's goal is still the combined system
(memory plus core). This study asks only what the relational core can represent and generalize.

## Question

The two-space core codes each item as an object code `c = E(x)`. A pair is coded in a relation space as `q = G([c_a, c_b])`,
and one shared reader judges it as `S([q, r])`, with `r` a learned code per relation. On a world of everyday facts:

1. Which kinds of relation does it learn: hierarchy, attributes, order, symmetry, inverses, composition and agreement?
2. Does it generalize to facts it was never taught, but which follow from the world's structure?
3. Does a new word or thing given only one or two facts take on everything implied by them (fast mapping)?
4. Does the relation space hold relations as abstractions? In particular, is the same relation coded alike for different
   items?

Each test has a **shuffled-world control**: every fact is kept, but the structure that implies the held-out facts is removed. Generalization
counts only where it beats that control.

## Inputs

**Symbolic, one-hot.** Each entity is one input unit, so `E` is an embedding table. One-hot is the fastest input, and it is
also the strictest test: no two items look alike, so everything an item means must come from its facts, with no
surface similarity to lean on. **Closed world:** the generator knows every fact, so every judgment has a true answer.

## The world

About 170 entities and 24 relations. The world is generated by `src/everyday_world.py` from hand-written tables
(deterministic; the tables are the specification). Each relation has a declared head set and tail set. A query is a
(head, relation, tail) triple with both ends in those sets. It is labelled true if the fact holds and false otherwise.

| Domain | Entities | Relations | Structure under test |
|---|---|---|---|
| **Animals** | ~30 animals in 6 classes (mammal, bird, fish, insect, reptile, amphibian), plus `animal` | `is-a`; `has` (fur, feathers, scales, wings, fins, beak, tail; legs 0/2/4/6); `can` (fly, swim, run, climb, sing); `lives-in` (water, land, trees, farm); `eats` (meat, plants, seeds, insects); `says` (moo, bark, …); `baby-of` (puppy, kitten, …) | class hierarchy, property inheritance, exceptions (penguin cannot fly; bat and whale are mammals; a bat flies) |
| **Colours** | 10 colours; ~20 coloured things (banana, grass, snow, sky, …), some of them animals (frog, flamingo, crow) | `colour-of`; `mixed-from` (orange ← red, yellow; …); `warm` / `cool` as a `has` tail | one-to-many attributes across domains; part-of mixing |
| **Size** | 12 animals in one size order (whale … ant) | `bigger-than` | transitive, antisymmetric order |
| **Opposites** | 8 adjective pairs (big/small, hot/cold, wet/dry, …) | `opposite` | symmetry |
| **Family** | two isomorphic trees of 12 people (after Hinton 1986), each person `male` or `female` | `parent-of`, `child-of`, `spouse-of`, `sibling-of`, `grandparent-of`, `has` (gender) | inverses, symmetry, composition, transfer between isomorphic trees |
| **Words** | singular and plural noun words for ~10 animals (`dog-w`, `dogs-w`); singular and plural verb words (`runs-w`, `run-w`, …); categories `noun`, `verb` | `is-a` (word category), `names` (word → animal), `plural-of`, `agrees` (subject noun word, verb word: same number), `can-subject` (true only if the named animal can do the action: `dogs-w` `run-w` yes, `dogs-w` `fly-w` no) | grammatical number and agreement; selection that ties grammar to meaning; the wug test (Berko 1958) |

**Language scope in v1.** The pair core reads pairs, not sequences. So v1 tests the word relations that grammar rests on:
category, number, agreement, and selection tied to meaning. It does not test sentence grammar: word order, agreement across
intervening words, or recursion. Sentences need a way to read sequences, which is a different question (see open
decisions).

## Held-out facts (the generalization tests)

Every test fact is excluded from training. Its reversed or related facts are kept or excluded as listed. Lists are fixed
in the generator, not sampled.

| Test | What is held out | Follows from |
|---|---|---|
| **T1 inheritance** | all `has`, `can`, `lives-in`, `eats` facts of one typical member per class (robin, salmon, dog, ant, lizard; frog keeps its facts, being its class's only member) | its `is-a` fact and its classmates |
| **T2 hierarchy** | `is-a(x, animal)` for 6 animals | `is-a(x, class)` and `is-a(class, animal)` |
| **T3 exceptions** | (a) penguin `can fly` = false is *trained*; read whether it is kept and whether it leaks to other birds. (b) the exception for one animal (a bat flies) is held out | (a) memory of an exception; (b) not inferable: expect the class default (overgeneralization), as children show |
| **T4 order** | `bigger-than` trained only on adjacent pairs in the size order, both orders (true/false); all non-adjacent pairs held out | transitivity |
| **T5 symmetry** | `opposite` trained in both orders for 5 pairs and one order for 3; `sibling-of` the same in tree B; reversed orders held out | the relation's symmetry on other pairs |
| **T6 inverse** | `child-of` held out for 6 people in tree B whose `parent-of` facts are trained | `parent-of` with the inverse pattern learned elsewhere |
| **T7 composition** | `grandparent-of` held out for half the pairs of tree B (all of tree A trained) | `parent-of ∘ parent-of`, plus the isomorphic tree |
| **T8 agreement** | `agrees` and `can-subject` held out for a quarter of (noun word, verb word) pairs; for 2 noun words, all of them | number on other pairs, and the named animal's abilities |
| **T9 cross-domain** | `colour-of` for 3 animals whose colour is shared with their non-animal objects | not inferable (control: should be at chance) |

T3b and T9 are **negative controls inside the real world**: the correct answer cannot be inferred, so above-chance accuracy
there would mean leakage or a bias, not abstraction.

## Fast mapping (after training, network frozen)

A new entity is added with a fresh code. Only its code is learned, from k ∈ {1, 2, 4} facts. Everything else is frozen.
Each of the 5 new entities is fitted separately:

| New entity | Facts given (k = 1 first) | Read |
|---|---|---|
| `dax` | `is-a(dax, bird)`; then `has(dax, beak)`, … | `has` feathers, wings; `can` fly; `is-a` animal |
| `fep` | `is-a(fep, fish)` | `lives-in` water; `has` fins, scales; `can` swim |
| `wug-w`, `wugs-w` | `plural-of(wugs-w, wug-w)`; `names(wug-w, dax)` | `agrees` with plural verb words for `wugs-w` and singular for `wug-w`; `can-subject` with `fly-w` (via dax) |
| `zorp` | `bigger-than(zorp, cat)`, `bigger-than(dog, zorp)` | order against all 12 animals |
| `kim` (person) | `child-of(kim, p)` in tree A | `grandparent-of` from p's parent, `sibling-of` p's children |

A **new relation** is learned in the same way: only its code is fitted, from 4 or 16 examples, with everything else
frozen. The new relations are `smaller-than` (the inverse of a known order), `same-class` (a, b in one class) and
`can-swim-and-fly`. Read on the relation's held-out pairs.

For each fitted code, a diagnostic: distance to its class centroid, compared with distances to other classes. Is `dax`
placed among the birds, or is it only somewhere that satisfies `is-a(dax, bird)`?

## Arms

| Arm | Scorer | Role |
|---|---|---|
| `two` | `S([G([c_a, c_b]), r])`, D = 32 | **the system** (as in equality v2's two-space base, with a one-hot `E`) |
| `two-16`, `two-64` | as `two`, D = 16 and 64 | pair-space capacity: G is relation-agnostic, so every relation of a pair must pass through D dims |
| `flat` | `S([c_a, c_b, r])`, D = 32 | no pair space (the count base's form); parameters matched to within 10% by S's width |
| `complex` | ComplEx (Trouillon et al. 2016), D = 32 complex | an established knowledge-graph model with a built-in bilinear form. **Comparison only**: the program's relational component may not have a built-in form |
| `prior` | per (relation, tail) base rate from training | trivial baseline; no learning about items |

`two` and `flat` are also run on the **shuffled world**. Each relation's heads are permuted independently, so every
relation keeps its statistics, but one entity's facts in different relations no longer belong together. Within-relation
structure (order, symmetry) is also broken, by permuting tails within each relation for those relations.

Seeds 400–403.

## Training

- Full labelled query set minus held-out, about 20–30k triples.
- Balanced BCE per relation (positive weight per relation), Adam lr 3e-3, 3,000 steps, minibatch 4,096. Every relation
  appears in every batch, in proportion to its size, with a floor so that small relations (`opposite`) are not starved.
- Weight decay 1e-4 on all arms (it limits memorization; ComplEx needs a regularizer as standard).
- No early stopping on test facts. A validation set of 5% of trained triples, drawn uniformly, is used only to report fit.

## Reads

**Primary**, per test T1–T9, per arm, mean and per seed:
- balanced accuracy at threshold 0, and AUROC;
- for (head, relation, ?) tests with one true tail (inverse, composition), the rank of the true tail among the relation's
  tails (hits@1, MRR).

Real world against shuffled world: `two` must beat its shuffled control by ≥ 0.10 balanced accuracy for a test to count as
generalized.

**Fast mapping:** read accuracy as a function of k; centroid diagnostic.

**Relation space (abstraction):** on true training pairs,
- a linear probe from q to the relation (5-fold, by entity, so test pairs share no entity with training pairs);
- an analogy read: for a true pair (a, b) of relation ρ, is the nearest q from pairs sharing neither a nor b also of relation ρ?
- the same q statistics on the shuffled world.

Also reported: train fit and how each held-out fact's reversed/related facts are judged (to separate "did not learn the
property" from "did not learn the support").

## Predictions

1. **[Rogers and McClelland 2004; Hinton 1986; familiar]** T1 inheritance and T2 hierarchy are well above shuffled in `two`
   and `flat` (≥ 0.85): embedding networks share codes among items with shared facts.
2. **[Saxe et al. 2019; familiar]** Broad class properties (`has` feathers) are learned before item-specific ones (`says`);
   logged as accuracy per relation over training (every 250 steps).
3. **[familiar]** T3a: the trained exception is kept (> 0.9). T3b: the held-out exception gets the class default (a bat is
   judged not to fly; balanced accuracy ≤ 0.5 there). That is the correct failure.
4. **[Lippl et al. 2024, transitive inference in networks; familiar]** T4: non-adjacent pairs above 0.8, better for
   larger rank distance (a symbolic distance effect). `complex` also learns the order: ComplEx can represent antisymmetric
   relations.
5. **[local: equality v2]** T5 symmetry and T6 inverse are above chance but below trained facts in `flat`. The prediction
   for `two` is uncertain. In equality v2 the two-space base inherited symmetry from collections; here no other input
   aligns the reversed pair.
6. **[Hinton 1986; CLUTRR; familiar]** T7 composition is the weakest structural test: above shuffled, below 0.8. The
   isomorphic tree helps only in so far as the two trees share code dimensions.
7. T8 agreement on held-out pairs is above 0.9 in `two` and `flat`: number is one shared feature. `can-subject` on held-out
   pairs is lower, because it needs the named animal's abilities read through `names`.
8. **[local: generic relations v1]** **Fast mapping at k = 1 is weak in `two` and `flat`.** A generic reader can be
   satisfied by a code that meets `is-a(dax, bird)` without lying among the birds. So untaught properties follow only
   partly (0.6–0.75), rising with k, with the centroid diagnostic tracking accuracy. `complex` is higher at k = 1, because
   its bilinear form ties the code to the bird direction. This is the prediction that matters most for the user's goal of
   teaching a new name for an understood concept.
9. `two-16` loses fit on relations with many tails, because of the D-dim pair bottleneck. `two-64` matches `flat`.
10. Relation probe from q is high (> 0.9) in the real world and lower on the shuffled world. The analogy read is lower than
    the probe.
11. T9 and shuffled controls are at chance.

## Prior work

Searched 2026-11-05 (queries: "Saxe McClelland Ganguli mathematical theory of semantic development"; "Rogers McClelland
semantic cognition"; "Hinton 1986 distributed representations family trees"; "Socher neural tensor networks knowledge base
completion"; "Kemp Tenenbaum discovery of structural form"; "ComplEx link prediction"; "CLUTRR"), plus the shared survey in
[prior work](prior-work.md).

- **This is knowledge-base completion on a small closed world.** Entity embeddings plus a learned scorer predicting held-out
  triples: Hinton's family trees (1986) **[search excerpts]**; ER-MLP / neural tensor networks
  ([Socher et al. 2013](https://www.cs.princeton.edu/~danqic/papers/nips2013.pdf)) **[search excerpts]**. These report
  86% on unseen WordNet relationships, with the bilinear and tensor forms ahead of a single-layer MLP scorer (76%).
  [ComplEx](https://arxiv.org/abs/1606.06357) **[abstract]** handles symmetric and antisymmetric relations. `flat` is the
  MLP scorer; `two` is an MLP scorer with a relation-agnostic pair bottleneck. **Predicted from theory/prior results:**
  inheritance-style generalization works for embedding scorers, and the bilinear form is a strong cheap baseline.
- **Semantic development.** [Rogers and McClelland 2004](https://www.cambridge.org/core/product/F3157F4E1DFF90DA60B0542E80586468)
  **[search excerpts]**: networks trained on item–relation–attribute facts (the canary network) differentiate broad
  categories first, then specific ones, and overgeneralize before learning exceptions.
  [Saxe, McClelland and Ganguli 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6561300) **[abstract]** derive this exactly
  for deep linear networks: modes are learned in order of their singular values. That gives predictions 2 and 3 without
  running.
- **Structural forms.** [Kemp and Tenenbaum 2008](https://pmc.ncbi.nlm.nih.gov/articles/PMC2492756) **[abstract]** infer
  which form (tree, order, ring) fits a domain, with the forms given as a grammar. That is the built-in-form approach the
  program excludes. It names the forms this world contains: tree (animals), order (size), pairs (opposites), family graph.
- **Composition and inductive reasoning.** [CLUTRR](https://arxiv.org/abs/1908.06177) **[abstract]**: kinship composition on
  unseen combinations is hard for text models, and graph models given symbolic inputs do better. **[familiar]** Path
  composition is a known weakness of single-hop scorers (path-ranking methods exist because of it).
- **Transitive inference.** **[familiar]** Networks trained on adjacent pairs of one-hot items often generalize to
  non-adjacent pairs with a distance effect (Lippl, Kay, Jensen, Ferrera and Abbott 2024, a theory of relational
  generalization in transitive inference; not re-read here).
- **Local results.** [Generic relations v1](generic-relations-v1-results.md) **[read: local]**: a generic comparator keeps
  taught judgments but places nothing that was only defined through relations. That is prediction 8.
  [Equality v2](equality-relations-v2.md) **[read: local]**: order generalization differs between the flat and two-space
  bases. That is prediction 5.
- **Known failure modes accepted:** fast mapping by fitting one code with a frozen reader can give an off-manifold code
  (measured by the centroid diagnostic, not prevented). One-hot inputs make the task harder than any real sense; a
  failure here is not a failure on perceived inputs.
- **What this adds:** a map, for the program's own core, of which relation kinds generalize and which do not, against the
  standard KB scorers and a structure-removed control, on one small world. Nothing in it is new to the field. The
  fast-mapping read is the part that bears directly on the program's goal.

## Scale

- A new entity costs D parameters, and a new relation costs one code (16). Training cost is linear in facts.
- Answering (h, r, ?) scores every tail: O(N · D · H) per query, with N entities and reader width H. This is linear in the
  world's size. A cosine prefilter on q or c (as in the memory line) would cut it; not used in v1.
- **The risk tested by `two-16`/`two-64`:** G does not see the relation, so q must hold everything about a pair that any
  relation reads. As relations grow, D must grow with them, or G must be told the relation (equality v2 does not).
- The world can grow by adding table rows; nothing in the code is specific to the domains.

## Computation (declared)

- **Parameters (`two`, D = 32):** E 170×32 = 5.4k; G (64 → 128 → 32) 12.4k; S (32 + 16 → 128 → 1) 6.4k; relation codes
  24×16 = 0.4k; about 25k in total (float32, about 100 kB). Adam state is twice that.
- **Per step:** 4,096 triples × (G + S) ≈ 4,096 × 19k MAC ≈ 80 MMAC forward. 3,000 steps ≈ 0.7 TFLOP including the backward
  pass. Estimate: about 1 CPU minute per run.
- **Runs:** main arms (`two`, `two-16`, `two-64`, `flat`, `complex`) × 4 seeds = 20 runs. Shuffled world (`two`, `flat`) ×
  4 seeds = 8 runs. Fast mapping: 5 entities × 3 k plus 3 relations × 2 sizes, 500 steps each, on frozen
  networks: about 15 s per run. `prior` is negligible.
- **Expected total:** under 1 CPU hour; about 5–10 min wall on 8 workers. No GPU.
- **Stored:** reports only (`reports/everyday-relations-v1.json`, `-runtime.json`). Weights go to `runs/` (not tracked),
  for the analysis of q.
- No tuning run: lr, steps and weight decay are fixed above. If a smoke run shows that `two` does not fit training facts
  (train balanced accuracy < 0.95), steps are raised once for all arms, and the change is recorded with its cost.

## Open decisions for the user

1. **Sentence grammar.** Should v1 stop at word relations (agreement, selection, the wug test), as drafted? Or should a v2
   add sentences, with a way for the core to read sequences? Options: pairs chained along a sentence, or a recurrent
   reader. That changes the architecture under test.
2. **Inputs.** One-hot as drafted (strict; meaning only from facts). An alternative is to give words a spelling-like
   input (so `dogs-w` resembles `dog-w`, and the plural `-s` is visible). That would test morphology too.
3. **Continual order.** v1 trains all domains together. A follow-up could teach domains one after another and read
   earlier ones afterwards (the program's rule that teaching B must not forget A). That is left out of v1, to keep the question to "what can it
   learn".
